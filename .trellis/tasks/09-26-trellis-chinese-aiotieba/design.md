# 技术设计

## 设计边界

本任务修改项目内 Trellis 定制，不修改 C# 产品功能或全局 Trellis 安装。它包含中文文案、使中文文案可被正确读取的最小兼容性修复，以及经用户明确授权的自动本地提交规则。保持既有任务创建、规划评审、实施、检查、归档顺序；自动提交授权只移除提交本身的重复确认。

## 内容归属与中文化范围

| 范围 | 处理方式 | 保持不变的内容 |
| --- | --- | --- |

## 最小解析兼容性调整

### 阶段与上下文

`common/workflow_phase.py` 和 `.codex/hooks/session-start.py` 目前按 `Phase Index` / `Phase 1: Plan` 定位。将当前可见标题改成中文，同时使两个入口接受原英文和新中文标题。保留 `#### 1.0` 等编号、平台块及 `[workflow-state:STATUS]` 标记；状态正文可以中文化。验证阶段索引非空、边界正确、不意外包含完整工作流，且各步骤和平台过滤保持原意。

`--json` 输出只翻译明确属于标题、说明等自然语言的值，不改变 schema、状态枚举、路径和 hook 外层字段。来自 Git、Python 标准库或外部 CLI 的原始诊断保持原样；本地上下文以中文说明其含义，不对第三方输出做全局替换。

### 日志与任务模板

`common/developer.py`、`common/task_store.py`、`add_session.py` 的新文档模板统一中文。同步日志标题、日期/统计字段、表头、旧记录扫描及幂等重试的消费者，使历史英文记录、中文记录和混合记录均可读取；保留指纹标记、计数和提交证据的事实。

测试使用临时目录和临时 Git 仓库，验证编号递增、索引更新、重复执行不重复追加、轮换与提交证据，不以实际归档当前规划任务来测试。

## 自动提交契约

用户已明确授权自动 Git 提交，该规则同时适用于本任务及后续常规已授权工作：

- 主会话完成检查和差异审阅，按职责清单自主暂存并创建中文说明的本地提交；无需再次提交确认。
- `trellis-implement` / `trellis-check` 继续负责实现与验证，禁止子代理抢先提交，避免并行修改被混合。
- 同步工作流阶段 3.4、状态提示、技能描述和 finish-work 路由；发现遗漏工作提交时由主会话回到 3.4 完成。
- 显式设置 `session_auto_commit: true`，`session_commit_message` 改为 `chore: 记录开发日志`；归档提交正文也中文化，保留已有范围隔离逻辑。
- 工作提交 → 任务归档提交 → 会话记录提交。保留真实历史提交标题；不用改写历史实现中文化。
- 不带入不属于任务的已暂存或未暂存工作；无变更不制造空提交；检查失败先处理阻碍。远程推送、历史改写不包含在此授权中。

## 版本管理与升级

`.gitignore:274` 当前忽略整个 `.agents`，46 份技能 Markdown 尚未跟踪。为使中文定制可保留，精确放行本任务使用的 `.agents/skills/trellis-*/` Markdown 和其目录，继续忽略其他代理状态、缓存及文件。不执行覆盖式 `git add -f`，也不取消整个 `.agents` 的忽略。

不重写 `.template-hashes.json` 的基线哈希。记录本地中文定制清单及升级后需要复核的解析器、技能、hook；未来遇到模板冲突保留本地中文规则后审阅上游变化。本轮不运行 `trellis update`。

项目自有规则放在 spec 或根管理块之外。捆绑技能仅做所请求的中文翻译及必要入口同步，不把库业务规则塞入其公共参考文档。

将指向本项目不存在的 Trellis 上游模板树或规格的说明标为上游专属，并将本地 hook 引用修正为真实路径；不为满足模板描述创建虚构目录或空规格。

## 风险与回滚

- 文案批量翻译可能误伤标记、链接和正则；通过结构检查、前后字段比较及针对性测试约束。
- 日志翻译可能破坏计数/幂等；先验证消费者兼容，再翻译历史记录。
- 工作区已有初始化改动；以实施前清单划定本任务所需文件并保留无关内容。实施时核实 `.gitattributes` 全部为 Trellis 说明与日志合并规则，故中文化其说明，保持规则不变。
- 回滚按本任务变更清单或后续提交执行；不重置整个工作区、不清理用户既有文件。

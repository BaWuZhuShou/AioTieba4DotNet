# 兼容性基线设计

## 公开元数据

在现有 Governance 项目增加 `PublicApiBaselineContractTests` 和可审阅的文本基线，建议位于 `Contracts/Baselines/public-api.txt`。使用现有测试依赖与 .NET 反射，不新增包。内部类型和生成 protobuf 不进入公开基线，但不能按目录漏掉实际公开的类型。

最低冻结维度：

- 对外可见类型的完全限定名、种类、可见性、泛型参数/约束、基类、接口、抽象/密封属性及嵌套关系。
- 公共及可由外部派生类访问的受保护构造器、方法、属性/索引器、事件、字段和运算符；记录静态/实例、访问器可见性、虚/抽象信息。
- 返回类型、参数类型/名称/顺序、`ref`/`out`/`in`、可选参数和默认值、`params`、可空性及相关修饰。
- 枚举底层类型和成员值、公开常量值、会影响调用或公开 DTO 序列化契约的现有属性标记。
- 明确哪些 CLR 元数据不在这份快照内，避免承诺覆盖未编码的维度。SDK、构建日期和机器路径不进入稳定文本。

先枚举现有公开形状，再确定序列化规则；不得仅使用 `MemberInfo.ToString()`。输出按 ordinal 排序，对泛型、数组、嵌套类型和默认常量采用确定性格式。测试只比较，不提供运行时自动接受差异的开关。基线生成是显式维护动作，记录产品来源提交。

以现有复杂公开形状和少量测试夹具证明默认值、枚举值、访问器、可空性及参数修饰能被区分。这些是对契约检查有效性的验证，不要求给格式化器每行添加镜像式测试。

该基线是静态契约保护，不单独证明全部二进制兼容性、序列化运行时行为或真实服务兼容性。调用行为由下面的表征和既有测试补充。

## 查询行为表征

在 Governance 增加 `ForumLookupBehaviorContractTests`，沿用受控 HTTP 核心和受控会话。产品已经向 Governance 开放 `InternalsVisibleTo`，优先直接使用内部测试接缝，避免新增反射构造框架。优先经过公开模块入口，确需观察内部操作名时使用最窄的已有接缝，不新增产品公共 API。

| 场景 | 断言 |
| --- | --- |
| GetFid 冷/热缓存 | 结果、HTTP 次数、双向缓存共享、0 不记为成功映射 |
| GetFname 冷/热缓存 | 详情请求次数；按响应 ID 的有条件写入和按请求 ID 的无条件写入都保留 |
| 详情/论坛资料回填 | 后续名称与 ID 查询复用同客户端缓存；保留空/空白条件差异 |
| 预先取消、请求中取消、服务端失败 | 异常身份/字段、无额外请求、失败后没有伪成功缓存；重试调用仍按现状加载 |
| Admin 冷缓存 | 参数校验 → 认证/TBS 前置 → ResolveFid 查询 → 管理操作的原有顺序及异常操作名 |
| Admin 热缓存 | 辅助解析短路但实际业务认证保留；不同无效参数组合的先报错行为保持 |
| 并发填充缓存 | 受控地在 Admin 认证准备期间填入缓存，证明当前实现仍执行原本的 ID 查询；用屏障而非 sleep |
| Thread.GoodAsync | 认证/TBS、ID、分类、加精顺序；空分类的短路行为保持 |
| 多入口和多客户端 | 直接/DI/工厂对象图约定沿用既有测试；同客户端共享、不同客户端不共享查询缓存 |

按照原代码选择能区分真实行为差异的最小用例组合。不要为每个只是转发的重载复制整套测试。重构阶段可以调整内部构造接缝，不得修改预期可观察结果。

## 验证与回退

完整命令在执行计划中。没有在线网络和凭据依赖。基线与测试为独立提交，之后产品重构即使回退仍可保留本提交。遇到现有行为缺陷先记录，不能在表征任务里偷偷改正。

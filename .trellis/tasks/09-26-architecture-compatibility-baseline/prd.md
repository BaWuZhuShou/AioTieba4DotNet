# 建立内部重构兼容性基线

## 目标与父任务

为 [内部架构演进](../09-26-internal-architecture-evolution/prd.md) 的首批解耦建立可重复、可审阅的兼容性基线。覆盖父任务 R1、R2、R4、R5；本子任务先于吧信息查询解耦执行。

## 已确认事实

- 原产品基线为 `b9a86af`。现有公开结构测试不足以代替完整的 API 元数据冻结；现有状态等离线契约可以复用。
- Forum/Admin ID 解析的认证、缓存和描述符名称存在差异。GetFname 的两次缓存回填，以及 Thread.GoodAsync 的分类查询也是需要保护的行为，具体定位见父任务的 [协议研究](../09-26-internal-architecture-evolution/research/protocol-dependencies.md)。
- 环境暂缺符合 `global.json` 的 SDK、还原和 Release 产物，四个必需证据文件也缺失，详见父任务 [兼容性研究](../09-26-internal-architecture-evolution/research/compatibility-baseline.md)。

## 需求

- A-R1：记录当前程序集全部对外可见类型和成员的指定元数据维度，不自动批准后续差异。
- A-R2：在产品重构前，用受控传输固定吧信息查询的可观察结果、网络调用顺序、取消、失败、认证和缓存行为。
- A-R3：保持产品代码、公开契约、已有治理阈值及 CI 规则不变；复用现有离线测试工具。
- A-R4：记录基线来源、执行命令和限制，不能从重构后的程序集反向生成“原始”基线。

## 验收标准

- [x] A-AC1：基线由未改产品代码构建生成，来源提交和 SDK 已记录；以确定性排序保存且可人工审阅。
- [x] A-AC2：元数据比较覆盖设计中列出的类型/成员、默认值、枚举及可空性等维度；代表性差异可以被检测，不将类名列表当成完整契约。
- [x] A-AC3：吧信息行为表征在原产品实现上通过，覆盖冷/热缓存、响应与请求 ID 不同、名称空白/空值边界、成功/失败/取消、管理认证顺序、分类查询及隔离。
- [ ] A-AC4：锁定还原、Release 构建及明确离线白名单通过后创建工作提交；证据检查的缺失如实记录。

## 范围外

不修改产品逻辑，不修正原行为，不触发在线操作，不升级依赖或框架，不补齐所有传输/签名测试，不将本子任务称为全部运行时或线上兼容性证明。

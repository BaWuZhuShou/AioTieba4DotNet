# 项目定位与 aiotieba 对齐

## 核心定位

AioTieba4DotNet 是以 [Python aiotieba](https://github.com/lumina37/aiotieba) 为功能与接口语义参照的 C# 实现。核心价值是让 C#/.NET 使用者方便地调用贴吧能力，并在不同宿主中复用同一套客户端库。

功能开发以对齐上游能力、参数含义、请求协议、返回数据和业务行为为目标，同时采用 C#/.NET 的类型、异步、异常、资源管理和依赖注入习惯。目标不等于当前已实现或已验证的覆盖范围。

当前维护线为 v3、`net10.0` / C# 14，依据 [构建设置](../../Directory.Build.props) 和 [v3 契约](../../docs/adr-v3-contract.md)。本项目是库；`backend` 规范覆盖库、生成器和测试支持，`frontend` 规范覆盖 VitePress 文档站。

## 使用场景与接入方式

设计与文档应考虑控制台工具、桌面宿主、服务和后台任务中的调用者，分别说明访客读取、认证后操作、吧务管理、消息与多账号需求。场景说明不自动扩大目标框架或平台支持承诺。

使用现有三种组合入口，详见 [入门指南](../../docs/guide/getting-started.md)：

- 直接构造 `TiebaClient`，用于简单工具和显式管理客户端生命周期的应用。
- `AddAioTiebaClient` / `ITiebaClient`，用于宿主应用的依赖注入。
- `ITiebaClientFactory`，用于独立创建不同账号的客户端。

三种入口共享公开能力和组合逻辑。账号与会话状态由各客户端拥有；多账号不能靠在共享单例上切换凭据实现。保持现有六模块边界、公开契约与协议无关 DTO，遵循 [目录规范](backend/directory-structure.md) 和 [会话规范](backend/session-and-cache.md)。

## 开发与审查必须核对的语义

任何新增或调整公开功能、协议、响应映射、默认值和错误行为的任务，都应记录以下内容。研究引用固定提交和具体符号；没有对应上游能力时明确写出依据与差异。

| 检查项 | 需要记录或验证的内容 |
| --- | --- |
| 对应入口 | 上游 Python 导出/客户端方法，C# 模块、公开成员和重载；内部请求存在不代表公开入口可用 |
| 输入 | 含义、类型、单位、范围、默认值、空值、页码、排序、特殊哨兵值；不因 Python 都用 `int` 就合并 C# 的不同整数类型 |
| 认证与状态 | 访客或凭据条件、TBS/WS 等准备步骤、状态提交时机、失败与取消后的状态 |
| 线协议 | URL、方法、表单/JSON/protobuf/WS、命令 ID、编码、cookie/header、签名字段顺序与兼容算法 |
| 响应 | 字段、枚举、顺序、分页/游标、缺失字段、默认值、错误信息及公开 DTO 映射 |
| 错误与取消 | 业务失败信息、.NET 异常适配、取消传播、回退条件，避免重复执行写请求 |
| 差异与证明 | 上游预期、当前实际、差异原因、验证命令、证据、当前状态与明确限制 |

实现前读 [传输规范](backend/transport-guidelines.md)、[映射规范](backend/mapping-and-codegen.md) 和 [异常规范](backend/error-handling.md)。公开行为变化需要同步用户文档、台账和使用技能，具体见 [质量规范](backend/quality-guidelines.md)。

## C# 适配边界

功能语义对齐允许语言层面的合适表达，但差异必须有说明，不能用“.NET 风格”笼统掩盖行为偏差：

- 使用 `Task` 或 `Task<T>`、`Async` 后缀和末尾可选 `CancellationToken`；不增加同步阻塞包装来模仿 Python 接口布局。
- 使用强类型参数、重载和公开 DTO 属性；保持 Python 接口名在台账中可反查，不把上游拼写错误擅自改成新的身份。
- 遵循现有 `IDisposable` / `using` 生命周期和 DI/工厂边界；未实现能力不得写成支持承诺。
- 固定版 Python 部分接口通过 `handle_exception` 把错误放进结果的 `.err`；现有 C# 接口通过异常表达失败。保留服务端错误信息和既定异常契约，记录可观察差异，不自行改成 `false` 或空 DTO。
- 取消保持取消；协议回退不能吞掉业务错误或改变写请求副作用。

## 验证与结论

优先选择与改动对应的离线契约：线协议、签名顺序、默认值、映射结果、状态恢复和传输选择。断言调用者可观察的结果；“没有抛异常”或日志输出本身不足以证明对齐。

分别报告以下事实：实现存在、离线契约通过、真实在线行为通过、覆盖率达标。构建或文档检查不能替代任何在线证明。`safe` 是包含真实写入及补偿的在线通道；它不是离线安全测试别名。

保留机器读取的状态值与表格格式，包括 `match`、`requires-remediation`、`upstream-gap`、`blocked-by-verification`、`intentional-divergence-approved`。最后一种状态需要明确批准证据，不能由实现者自行认定。单行 `match` 也不能扩展成全库已完全对齐。

缺失上游快照、保留产物、凭据或运行条件时，如实记录限制，不编造证据或降低门槛。当前 checkout 是否具备证据应当现场检查，不能把旧规范的观察当成永久事实。

# 本地 Trellis 中文化与自动提交契约

## 1. 适用范围与触发条件

本项目 Trellis 的自然语言默认使用简体中文，包括工作流、规范、技能及引用说明、代理提示、配置注释、本地脚本提示、任务产物、检查报告和会话记录。修改这些内容或升级 Trellis 时，必须同时检查生成端和读取端。

本规范是项目自有约定。根 `AGENTS.md` 管理块之外的入口指向本文件，项目定位见 [项目定位与 aiotieba 对齐](project-positioning.md)。不要把本项目业务规则塞入捆绑技能的公共参考文档。

## 2. 命令与入口

```bash
python3 .trellis/scripts/get_context.py --mode phase --platform codex
python3 .trellis/scripts/get_context.py --mode phase --step 3.4 --platform codex
python3 .trellis/scripts/task.py current --json
python3 .trellis/scripts/task.py validate <task-dir>
python3 .trellis/scripts/add_session.py --title "会话标题" --commit "<真实提交哈希>" --summary "中文摘要"
python3 -m unittest discover -s .trellis/scripts/tests -p 'test_*.py'
```

中文任务标题仍显式提供稳定的 `--slug`，不改变目录命名、命令参数或状态枚举。子代理调度的首行 `Active task: <task-path>` 是兼容性契约，保留原文。

## 3. 生成与读取契约

### 可翻译与保留内容

自然语言标题、正文、注释、docstring、帮助、提示和模板说明可翻译。代码标识、路径、参数名、JSON/TOML/YAML 键、枚举、事件名、原始提交标题、哈希、外部输出匹配和协议标记保持原样。代码块中的文字要按含义分类，不能整块机械替换。

保留 `TRELLIS:START/END`、`[workflow-state:STATUS]`、平台标签、步骤编号、`@@@auto:*`、`trellis-session` 指纹和 `trellis-hook-injected`。第三方 CLI、Git、宿主和标准库原始诊断允许英文；本地解释使用中文。

### 阶段与日志

- 当前工作流可见标题为 `## 阶段索引`、`## 阶段 1：规划`；阶段读取器及 SessionStart 入口也接受原来的 `## Phase Index`、`## Phase 1: Plan`。
- 步骤使用原有 `#### 1.0` 等编号。翻译不能使索引为空、越过边界或丢失平台分支。
- 新日志使用 `## 会话 N: 标题`、`**日期**:`、`**会话总数**:` 和中文表头。读取器同时支持英文旧记录及中英混合记录，包括旧四/五/六列表头。
- 编号统计、跨 Git 引用查询、日期、轮换和幂等重试都必须支持中文。翻译历史记录保留真实日期、结果、哈希与指纹，不重算历史身份。
- 默认摘要也参与会话指纹时，显示文案与机器身份必须分开：新记录显示中文，旧版未完成记录重试仍使用兼容的默认身份。仅对已知默认占位摘要作归一，不更改用户实际摘要或历史哈希。
- 历史“当时要求英文”属于事实，应翻译并标明当时范围；不得继续作为当前语言规则。
- `.gitattributes` 对仅追加的 `journal-*.md` 保留 `merge=union`。个人索引不能套用同一规则；出现冲突时结合保留日志重新生成或核对，任务状态仍以 `task.json` 为准。

### 中文上下文与字节预算

注入预算按 UTF-8 字节计数。截断点恰好位于完整汉字或其他多字节字符末尾时，应保留整个字符；落在字符内部时丢弃不完整的末尾序列。结果必须可按 UTF-8 严格解码，不能以替换字符 `U+FFFD` 掩盖边界错误，也不能超出原有字节预算。

### 自动本地提交

用户已授权：本任务及后续已授权开发任务在检查通过后，由主会话自主审阅差异、按范围暂存并提交，无需再询问是否提交。提交标题使用约定类型前缀和中文说明。

工作成果提交、任务归档提交、会话记录提交按此顺序完成。显式启用 `session_auto_commit: true`；`session_commit_message: "chore: 记录开发日志"` 只控制日志提交，不能代替主会话提交工作成果的职责。

子代理只实施、检查和回报，由主会话统一提交。使用精确文件清单/pathspec，保留无关的已暂存和未暂存内容；同文件存在无关修改时须先划清差异范围，不能直接整文件纳入。归档只纳入当前任务及明确关联的变更，不能把整个 `archive/` 目录当作提交范围。不得为自动提交扩大忽略规则或把缓存、凭据加入仓库。

没有变更不创建空提交；检查失败先修复或报告实际阻碍。自动本地提交不包含远程推送、改写历史或跳过验证。用户后续明确要求暂停提交或自行提交时，以新的要求为准。

## 4. 验证与错误矩阵

| 条件 | 应有结果 |
| --- | --- |
| 中文阶段标题或旧英文标题 | 索引、步骤和平台路由均能读取，范围正确 |
| 中文、英文或混合日志 | 编号递增、日期与索引正确，重试不重复追加 |
| 新建任务或开发者日志 | 模板自然语言为中文，机器字段不变 |
| JSON/JSONL 或 hook 输出 | 结构与字段名不因翻译改变，UTF-8 与预算处理有效 |
| 无关文件已暂存 | 本任务及归档/日志提交不包含它们，原暂存状态保留 |
| 无变更或检查失败 | 分别跳过空提交，或处理阻碍后再提交 |
| 旧证据缺失、外部工具英文诊断 | 如实报告，不捏造通过记录，不翻译外部输出匹配字符串 |

## 5. 正常、基准与异常情形

- 正常：中文任务完成相关检查，主会话提交相关文件，再归档并生成中文日志。
- 兼容基准：旧英文日志后追加中文日志，编号连续，旧提交标题和指纹保持原样。
- 异常：只翻译 `Session` 标题而不改编号消费者，可能导致历史最大编号无法读取；此类变更必须与读取端及回归检查一起交付。

## 6. 必要验证

使用本地标准库测试覆盖阶段提取的两个入口、中文/英文/混合日志、表头迁移、编号/轮换/幂等、新任务模板、hook 结构及精确提交范围。产生 Git 提交的验证必须在临时仓库进行，不污染真实任务和日志。

文案检查包括 UTF-8、Markdown 链接与代码围栏、索引、机器标记、JSON/JSONL/TOML/YAML 结构及残留英文分类。不能把“没有 ASCII 字母”当作中文化验收，也不能为了文案验证运行 .NET 在线测试。

## 7. 常见错误与正确处理

| 错误做法 | 正确处理 |
| --- | --- |
| 全文替换所有英文字符串 | 区分自然语言、代码标识与外部输出匹配，逐类处理 |
| 只改工作流标题 | 同步阶段查询与 SessionStart 两处消费者并验证旧格式 |
| 只开启 `session_auto_commit` | 同步主会话阶段 3.4 和收尾路由，明确工作提交责任 |
| 裸提交吞入其他人的 staged 文件 | 审阅任务范围，用精确路径或明确选择的差异提交 |
| 改模板哈希，让更新器把定制当原模板 | 保留 `.template-hashes.json` 基线，以便识别本地修改 |
| 删除整个 `.agents` 忽略规则 | 只放行 Trellis 技能 Markdown，保留其他本地代理文件忽略 |

Trellis 升级时复核工作流、技能、代理、hook、阶段/日志解析和生成模板；保留本地中文及自动提交规则，再合并上游变化。不要直接修改全局安装或新建本项目不存在的 Trellis 上游模板树。

# Trellis 规范初始化

使用本技能，基于真实代码库创建或刷新 `.trellis/spec/` 指南。由一个具备相应能力的代理负责完整闭环：分析仓库、确定规范边界、编写文档、验证结果。流程不依赖特定宿主、CLI 或代理品牌。

## 工作流

1. 确认 Trellis 已初始化，并检查现有 `.trellis/spec/` 目录树。
2. 使用可用的最佳工具分析仓库架构：GitNexus、ABCoder、语言工具和直接阅读源码。
3. 只有符合真实代码结构时，才按包和层拆分规范工作。
4. 以项目中的具体模式、文件路径、示例和反模式补充或重塑规范文件。
5. 验证最终规范内部一致，且不包含模板占位内容。

## 操作规则

- 模板是起点，不是契约。按仓库实际需要删除、重命名、拆分或新增规范文件。
- 优先采用有源码依据的规则，而非泛泛建议。每项重要建议都应指向真实文件或反复出现的本地模式。
- 默认由单一负责人执行。可选辅助代理只是实现细节，不是必要条件，也不是用户必须处理的依赖。
- 除非目标项目已统一使用某个平台，否则不编写平台专属指令。
- `.trellis/spec/` 中不得留下占位文本、空标题或照搬的样板内容。

## 完成标准

- `.trellis/spec/` 描述项目当前的真实情况。
- 每个相关包或层都有可操作的编码指南和真实示例。
- 不适用的模板章节已移除。
- `index.md` 与最终规范文件集合一致。
- 必需的配置或分析假设已记录到相关规范或任务笔记。

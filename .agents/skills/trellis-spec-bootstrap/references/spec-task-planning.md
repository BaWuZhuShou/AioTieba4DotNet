# 规范任务规划

默认采用单代理执行模型。代理可以创建 Trellis 任务以便追踪，但本技能不应要求特定平台、CLI 或并行 worker 模型。

## 拆分

围绕真实职责边界创建规范工作单元：

- 某个包有独立约定时，以包为单位。
- 同一包有明显不同的前端、后端、CLI、worker 或共享库规则时，以层为单位。
- 模式跨多个包且不属于单一层时，建立一份横向指南。

避免人为拆分。小型库通常只需一轮聚焦的规范编写，无需多个任务。

## 任务结构

适合使用 Trellis 任务时，用以下章节编写简洁 PRD：

```markdown
# 完善 <package-or-layer> 的 Trellis 规范

## 目标
为 <scope> 编写项目专属的 `.trellis/spec/` 指南。

## 范围
- 规范目录：
- 需检查的源码目录：
- 需检查的测试：
- 范围外：

## 架构上下文
总结仓库分析得到的具体发现。

## 待创建或更新的文件
- `.trellis/spec/.../index.md`
- `.trellis/spec/.../<topic>.md`

## 规则
- 按真实代码库调整规范文件集合。
- 使用真实源码示例并注明文件路径。
- 移除不适用的模板章节。
- 除非任务明确要求，否则不修改产品源码。

## 验收标准
- [ ] 规范包含仓库中的具体示例和反模式。
- [ ] 没有残留占位文本。
- [ ] 索引文件与最终规范文件一致。
- [ ] 所有结论均有源码、测试或项目文档依据。
```

## 可选辅助代理

宿主支持子代理时，可用辅助代理检查独立包或执行验证。它们是可选项；主代理仍负责集成和最终质量。

辅助任务必须有明确职责：

- 只读研究任务可检查分配范围所需的任意源码。
- 写入任务应分别负责不重叠的规范目录。
- 验证任务应检查占位内容清理、失效链接和一致性。

不要在技能中固定辅助代理名称、厂商专用命令或平台专属路由。任务只记录必需工作和验收标准。

# 完成收尾

收尾当前会话：归档活动任务，以及用户希望同时清理的其他已完成未归档任务，再记录会话日志。工作代码提交归工作流阶段 3.4；主会话应在进入本技能前完成，发现遗漏时先返回该步骤自主提交，再继续收尾。

## 步骤 1：查看当前状态

```bash
python3 ./.trellis/scripts/get_context.py --mode record
```

输出包括：

- **我的活动任务** — 检查除当前任务外是否还有已经完成（代码已合并、验收标准已满足）、适合本轮归档的任务。
- **Git 状态** — 快速查看未提交变更。
- **近期提交** — 步骤 4 的 `--commit` 需要工作提交哈希。

若 `--mode record` 显示与当前会话无关的其他已完成任务，一次性向用户确认：“这 N 个任务看起来已完成，本轮是否一并归档？[y/N]”。默认不归档额外任务；当前已完成的活动任务始终在步骤 3 归档。

## 步骤 2：检查并分类未提交路径

运行：

```bash
git status --porcelain
```

先排除 `.trellis/workspace/` 和 `.trellis/tasks/` 下的路径；它们由 `add_session.py` 和 `task.py archive` 的自动提交管理，本技能执行时本来就会产生这些变更。

将剩余路径分为**当前任务**或**其他并行工作**（例如另一个终端正在修改同一仓库）。判断依据：

- 当前任务 `prd.md` / `implement.jsonl` / `check.jsonl` 引用的路径 → 当前任务
- 所属代码区域符合任务范围，或本会话确实编辑过 → 当前任务
- 位于无关区域，且本会话未编辑 → 其他并行工作

随后按以下规则处理：

- **仍有当前任务的未提交变更** — 主会话说明具体文件，返回阶段 3.4，完成必要检查及精确范围提交，然后继续本技能。用户已经授权自动本地提交，不要求用户自行提交，也不再次询问常规提交确认。不要把工作提交混入归档脚本；子代理不得代替主会话提交。
- **其余路径均为无关工作** — 简要报告并继续步骤 3：
  > “以下变更不属于本任务，保留给其他工作处理：<路径列表>。”
- **依据现有证据仍无法确定归属** — 只针对这些路径向用户澄清一次：“这些文件属于本任务遗漏的变更，还是其他并行工作？”按回答路由；不得把来源不明内容夹带提交。

## 步骤 3：归档任务

```bash
python3 ./.trellis/scripts/task.py archive <task-name>
```

至少归档当前已完成的活动任务（若存在），再归档步骤 1 中用户确认的其他任务。每次归档由脚本自动创建 `chore(task): 归档 ...` 提交。

没有活动任务，且用户未确认额外清理时，跳过本步骤。

## 步骤 4：记录会话日志

```bash
python3 ./.trellis/scripts/add_session.py \
  --title "会话标题" \
  --commit "hash1,hash2" \
  --summary "简要摘要"
```

`--commit` 使用阶段 3.4 产生的**工作提交哈希**，可从步骤 1 的近期提交或 `git log --oneline` 获取。不要包含步骤 3 的归档提交哈希。脚本随后创建 `chore: 记录开发日志` 提交。

最终提交顺序：阶段 3.4 的工作提交 → 一个或多个 `chore(task): 归档 ...` → `chore: 记录开发日志`。

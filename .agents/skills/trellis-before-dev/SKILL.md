---

开始任务前，阅读相关开发指南。

按以下步骤执行：

1. **读取当前任务文档**：
   - `prd.md`：需求和验收标准
   - `design.md`（若存在）：技术设计
   - `implement.md`（若存在）：执行顺序和验证计划

2. **发现包及其规范层**：
   ```bash
   python3 ./.trellis/scripts/get_context.py --mode packages
   ```

3. **判断任务适用的规范**，依据包括：
   - 修改哪个包，例如 `cli/`、`docs-site/`
   - 工作类型，例如后端、前端、单元测试、文档
   - 任务文档引用的规范或研究路径

4. **阅读每个相关模块的规范索引**：
   ```bash
   cat .trellis/spec/<package>/<layer>/index.md
   ```
   遵循索引中的**开发前检查清单**。

5. **阅读清单中与任务相关的具体指南**。索引是入口，不能代替实际指南，例如 `error-handling.md`、`conventions.md`、`mock-strategies.md`。阅读这些文件，理解编码标准和模式。

6. **始终阅读共享指南**：
   ```bash
   cat .trellis/spec/guides/index.md
   ```

7. **非简单任务在编码前说明变更边界**。满足任一条件即属于非简单任务：涉及多个文件、跨层、改变公共接口，或修改并非刚刚编写的代码。写明：
   - 当前行为与目标行为之间最小的缺口
   - 该行为实际位于哪里，而不是哪里最方便拦截
   - 预计修改哪些文件，以及每个文件为什么必须修改
   - 本任务明确不做哪些内容
   - 若需要局部重构，如何证明行为保持不变

   范围明确的小修改无需此步骤，可直接执行。

   若实际范围明显更大，继续前先说明扩大之处和原因，不自行扩大变更。

8. 理解需要遵循的编码标准和模式后，再执行开发计划。

编写任何代码前，**必须**完成此步骤。
